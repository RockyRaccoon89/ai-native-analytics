# How to contribute
- coherence is important in a code base, coherence is especially important for a book that is meant to read start to finish
- the editor set the vision and the structure while the contributors add their expertise. it is encouraged to proposed changes to the vision and structure but the editor has veto on all decisions.
- it is strongly suggested to start exploring the Discussion channel before opening issues
**In summary**
1. start by reviewing the discussions and issues to see if something related to your proposed change was already documented
2. create a well documented issue based on the outcome of the discussion
3. the editor will review the issue and will comment and/or move it to backlog
4. create a branch and attach it to the issue
5. once your work is done, do a Pull Request that will be reviewed by the editor
